# PT100 temperature step investigation, 2026-09-09

All event times below are Europe/Zurich. The historical configuration register
was not logged, so the original hardware state cannot be proven retrospectively.

## Recorded events

| Time | Inner PT100 step | Outer PT100 step |
| --- | ---: | ---: |
| 2026-09-08 21:33:03 | +4.91 °C | +5.26 °C |
| 2026-09-08 21:47:19, restart/upload | -5.01 °C | -5.30 °C |
| 2026-09-09 14:44:36 | +4.97 °C | +5.25 °C |
| 2026-09-09 22:44:18, same-firmware restart | -5.08 °C | -5.26 °C |

Both upward events coincided with missing SCD41 readings. Today's first returning
SCD41 measurement had a different serial number. This is a correlation;
an electrical disturbance or converter reset during sensor replacement has not
been directly measured.

## Reproduction on the installed hardware

Temporary firmware 2.0.6 took four pairs at sequences 7–10 of boot 3797756211,
around 22:59:55–23:00:10. Each pair used the same PT100, reference resistance and
50 Hz filter. Only the MAX31865 three-wire compensation bit changed for the
separate diagnostic conversion. The ordinary readings retained compensation.

| Sequence | Inner normal | Inner uncompensated | Outer normal | Outer uncompensated |
| --- | ---: | ---: | ---: | ---: |
| 7 | 26.21 | 31.32 | 24.61 | 29.83 |
| 8 | 26.21 | 31.32 | 24.58 | 29.83 |
| 9 | 26.24 | 31.28 | 24.58 | 29.77 |
| 10 | 26.21 | 31.35 | 24.58 | 29.83 |

All temperatures are °C. Mean increases: inner **5.10 °C**, outer **5.23 °C**.
Both fault registers remained zero. The normal inner raw count was 9028–9029;
uncompensated it was 9189–9191, matching the approximately 9190 observed before
the restart. The guard restored configuration 0x01 to 0x11 on the following
ordinary reading. The resulting eight counted corrections in this diagnostic
boot were intentional mode changes, not eight spontaneous failures.

The test strongly supports loss of three-wire compensation as the mechanism.
The exact trigger of the earlier configuration loss remains unknown.
The preceding 50/60 Hz comparison had only small differences (maximum 0.06 °C
inner and 0.03 °C outer), which did not reproduce the step.

## Driver issue and protection

Arduino_PortentaMachineControl 1.0.5 sets the three-wire bit only in `begin()`.
A MAX31865-only reset clears its configuration. Restoring just the filter bit
then leaves lead resistance uncompensated until the next full initialization.
The [MAX31865 datasheet](https://www.analog.com/media/en/technical-documentation/data-sheets/MAX31865.pdf)
describes configuration register D4 and its lead-resistance compensation.

Firmware 2.0.7 reasserts and verifies the fixed converter configuration before
each conversion and checks it again afterward. Failed checks invalidate the
sample. Raw counts, before/after registers and correction-attempt counts are
stored in SQLite as well as API/QSPI records. Simulated converter resets,
including a reset during conversion and failed register writes, are tested
against the generated production driver using register-level SPI fakes.

The temporary comparison is disabled in 2.0.7. The SCD41 offset remains fixed
at 2.2 °C. Historical measurements are preserved without retroactive correction.
The local raw comparison is stored at
`logger/data/recovery/lead_compensation_comparison_20260909.ndjson` (ignored data).

Build and all 20 automated tests passed. OTA deployment of 2.0.7 was verified
on the device with boot ID 889078918. All sensors returned valid values, both
converter configurations remained 0x11 and the correction counter was zero.
The restarted logger stored these diagnostics in the existing database; a
consistent SQLite backup was taken before its schema migration.
